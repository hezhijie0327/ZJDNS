注（2026-08-08 下午）
---------------------
- UDP 系（udp/quic/dtls/dnscrypt/dtlcp）当前机器 ~3-7k QPS：1 并发与 32 并发
  吞吐相同（~6.7k），为机器 UDP 处理上限（旧代码同机同样 6.7k，已用 worktree
  d8d2c43 验证；文件 DB 同样 6.6k——与 DB 无关）——非代码回归；旧基线（上午
  23k）为更空闲机器状态所测
- DB 方案对比（benchclient TCP/TLS, 32 并发）：单连接 :memory:（旧）~7k
  （连接饥饿——MQTYPE hang 根因）；shared-cache :memory:（当前）40.9k/104.8k；
  文件 DB（WAL 多连接）29.5k/65.7k。shared-cache 内存 DB 整体最快（磁盘 IO
  开销 > shared-cache 锁开销）；zone 微基准 +44% 为 shared-cache 锁代价，
  换连接不饥饿
- TCP 系（tcp/tls/https/tlcp/http-tlcp/dnscrypt-tcp）40-105k QPS，较旧基线
  快 2-4 倍（缓存命中直发 + 连接池优化生效）
- http-tlcp 0.6% fail（connection reset by peer）：HTTP keep-alive 连接被
  服务端空闲关闭后客户端复用 stale 连接——连接重用现象，非服务端错误
- tls 28 fail（0.001%）：DoT 连接建立竞争，同旧基线量级
