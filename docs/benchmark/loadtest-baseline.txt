- Go: 1.26.5
- 服务端: 全协议监听 + pprof, zone 规则 www.bench.test (1.2.3.4), log_level=error
- 客户端: 32 并发（协议表）; 每协议 15s 一轮

修复前对照（本会话发现并修复的问题）
-----------------------------------
- quic:   78 QPS（32 并发）→ 22971 QPS（30s, 689142 查询, fail 1）
          根因: MaxIncomingStreams=256 秒级耗尽流配额 + quic-go 25ms ACK 延迟
- tcp:    1.5% 查询报 ID mismatch（5812/371069）→ 0
          根因: pool 失败后 fallback 复用残留 trackingID 的 msg.Data
- dtlcp:  并发客户端握手全失败（0 QPS）→ 25441 QPS
          根因: gotlcp 共享 UDP socket, 同步 accept 时新客户端握手包被偷
          修复: 服务端 per-client 数据报多路复用（demuxPacketConn）

备注
----
- 单连接 DTLCP 中间基线（demux 前, 32 worker 串行化）: 9683.7 QPS

  / 4b75532 (DTLCP demux 并发) / 6efa4e8 (缓存查询去 ORDER BY, QPS +12~24%)
